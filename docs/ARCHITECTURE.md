# 架构与关键取舍

> 这份文档只写「为什么这么做」。踩过的具体坑在 `工程约定-*.md` 与代码注释里。

## 1. 为什么内容必须走服务器（2.0 的核心决定）

1.0 是「客户端解析 RSS + 端侧转写」，两个问题在真机上都无法接受：

| 问题 | 现象 |
| --- | --- |
| 端侧转写 | 一个 12 分钟的节目在中端机上要 3–8 分钟，通勤时等于没有；APK 还会因为模型和 AAR 涨到 169 MB |
| 客户端直连源站 | 部分源站在大陆不可达；各 CDN 对不同的请求返回不同的音频拼接（广告），字幕必然错位 |

2.0 把这两件事都搬到服务器：**音频、字幕、封面全部自托管**，客户端只认一个目录文件。
收益：APK 18 MB、打开即可播、字幕与音频严格对应；代价：多了一台机器（2 核 2G 够用）。

## 2. 分层

```
┌────────────── app/ ──────────────┐
│ ui/        界面（Compose）         │
│ content/   目录 → 本地索引 → 下载   │  ContentRepository：唯一内容真相源
│ player/    Media3 + 字幕同步        │  NowPlaying：跨页面的播放状态
│ word/      生词本 + FSRS-6          │  WordStore：卡片 + 复习事件
│ checkin/   打卡（按天的时间轴）      │  CheckInStore：mine + others
│ sync/      账号与多设备同步          │  与 checkin/word 解耦
│ notify/    每日提醒（本地闹钟）      │
└──────────────────────────────────┘
                 │ HTTPS
┌────────────── server/ ────────────┐
│ api/       FastAPI：账号 / 同步 / 清单 │
│ bin/       cycle.py 定时流水线        │
│ nginx/     静态资源 + 反代（模板）     │
└──────────────────────────────────┘
```

## 3. 内容流水线（`server/bin/cycle.py`，每 30 分钟一轮）

```
读 feeds.txt（16 源）
  → 并发拉 RSS，按 72 小时窗口 + 单集时长上限（2h）筛选
  → 音频：下载到暂存区 → 转写（faster-whisper）→ 重切成句 → 翻译
  → 入库：音频移入 publish 区，字幕/译文/封面各自落盘
  → publish()：**只发布真的存在的东西**，生成 index.json
```

三条纪律：

1. **发布闸门**：字幕或译文文件不在 ⇒ 当期不发布（否则客户端拿到「有音频没字幕」，
   而 2.1.0 之后端侧没有兜底，等于不可用）。但配了熔断：缺中文比例 > 50% 判定系统性故障，
   宁可发出去也不交出空清单。
2. **地址逐条决定**：`audioUrl`/`artworkUrl` 只在文件真的存在时才写托管地址，否则退回原地址。
   好处是自愈——文件被保留期清掉，条目自动降级。
3. **抓图要换源**：NPR 的封面走 `brightspotcdn` 的 `dims3/...?url=<S3>` 代理，对本服务 403；
   而 `?url=` 里的 S3 源图可用。失败即换源，并统一压到 ≤512px（6.7 MB → 约 40 KB）。

## 4. 同步模型：打卡与生词本是**两套**

| | 打卡 | 生词本 |
| --- | --- | --- |
| 数据性质 | 只增的计数（今天听了多少秒） | 可变状态 + 可删除 |
| 合并 | 每设备一列，服务端**求和**（`MAX(旧,新)` 幂等） | 复习事件取**并集**，状态由客户端**重放** |
| 状态存哪 | 服务端表里 | **只在客户端**（状态的投影） |

- 打卡：`存在 ⟺ addedAt > deletedAt` 那套不适用；这里的关键是
  **客户端只写自己那一列，服务端求和**，客户端显示 `mine + others`。
  ⚠️ 算 `others` 必须**减掉本机**，否则「数字莫名变大」。
- 生词本：删除用两个只增的时间戳；复习事件的并集重放（4.1.0 把 FSRS 的抖动改成
  由「这次复习」派生，重放才能与增量逐字节一致）。

## 5. 内容策略（客户端）

- **懒加载**：只预取「接下来 N 条 + 收藏 + 正在播 + 每源保底各一条」。
- **每源保底不能省**：周更源不预取 → 没音频 → 被保留期清理 → **整个源消失**。
- **边下边播**：点了就先播、同时落盘；顺序不能反（登记下载会拉起更新服务，挡住起播）。
- **保留期**：本地 3 天，服务端 7 天（服务端必须严格大于本地，否则「本地删了还能重下」不成立）。

## 6. 每日提醒：为什么不是推送

FCM 在大陆无 GMS 不可用；四家厂商推送（小米/OPPO/vivo/荣耀）**全部要求企业开发者认证**，
小米/OPPO/vivo 还要求应用上架。而「每天固定时刻提醒一下」不需要服务器：

- 本地 `AlarmManager`，进程被杀也能触发（开机 / 装新版本后重排）；
- 三级退路：`setAlarmClock`（不受 Doze 推迟）→ `setExactAndAllowWhileIdle` → `setAndAllowWhileIdle`；
- **今天已达标就不提醒**——达标后的提醒是噪音，会让人整个关掉。

详见 `docs/推送与每日提醒-技术调研.md`（含四家接口事实与资质要求）。

## 7. 可扩展点

| 想加什么 | 从哪改 |
| --- | --- |
| 新内容源 | `server/bin/feeds.txt` 加一行 + `app/.../content/FeedSource.kt` 加一个对象（两边 id 必须一致） |
| 换转写模型 | `cycle.py --model` / `transcribe.py` 的默认值 |
| 更多复习维度 | `word/Fsrs.kt`（算法是 py-fsrs 的移植，`FsrsTest` 有向量对照） |
| 服务端换成 Postgres | `server/api/db.py` 是唯一的数据访问层 |
