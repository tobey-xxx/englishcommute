# 推送与「每日提醒」技术调研

> 结论先行：**你要的「每晚 23:30 提醒」不需要任何厂商推送**，本地闹钟就能做到，
> 而且断网也能响。四家厂商推送**全都要求企业开发者认证**（小米 / OPPO / vivo
> 还要求应用上架），个人开发者拿不到 —— 这是硬门槛，不是努力能绕的。

---

## 1. 先说清一件事：FCM、厂商推送、本地闹钟，是三样东西

| | FCM（安卓自带） | 厂商推送（小米/OPPO/vivo/荣耀） | **本地闹钟** |
| --- | --- | --- | --- |
| 大陆可用 | ❌ 没有 GMS，基本不可用 | ✅ | ✅ |
| 进程被杀后 | ❌ 收不到 | ✅ 系统长连接投递 | ✅ 系统按时刻拉起 receiver |
| 需要网络 | ✅ | ✅ | ❌ **断网也能响** |
| 需要服务器 | ✅ | ✅（四家各一套鉴权 + 接口） | ❌ **完全不需要** |
| 需要企业资质 | ❌ | ✅ **四家都要** | ❌ |
| 需要上架应用商店 | ❌ | 小米 / OPPO / vivo **要**（荣耀不要求上架） | ❌ |
| 包体增加 | — | 约 4~6 MB（四个 SDK） | 0 |
| 适合什么 | 海外 | 召回 / 运营推送（用户从没打开过也能收到） | **固定时刻的提醒** |

⚠️ 你在需求里说的「安卓自带的推送在大陆无效」——**对，指的是 FCM**。
但「每天 23:30 提醒我」这件事**根本不需要推送**：它不需要服务器算任何东西，
也不需要「即使从没打开过 App 也能收到」。所以这一版做的是本地闹钟。

## 2. 四家厂商推送的接口事实（本轮查证）

| | 小米（MiPush） | OPPO PUSH | vivo Push | 荣耀 Push |
| --- | --- | --- | --- | --- |
| 账号资质 | **企业**开发者 | **企业**开发者 | **企业**开发者 | **企业**开发者 |
| 是否要求上架 | **是** | **是**（或「不上架申请」） | **是** | 不要求上架 |
| 鉴权 | `Authorization: key=<AppSecret>`（**key 必须小写**） | `POST /server/v1/auth`（app_key + sign + timestamp）→ `auth_token`，24h | `POST /message/auth`（appId + appKey + timestamp + sign）→ `authToken`，24h | OAuth2（client_credentials）→ `access_token` |
| 发送 | `POST https://api.xmpush.xiaomi.com/v3/message/regid` | `POST /server/v1/message/notification/unicast` | `POST /message/send` | `POST https://push-api.cloud.honor.com/v1/{appId}/messages:send` |
| 消息形态 | `title` + `description`（**都必填**，title ≤50 字符、description ≤128）+ `pass_through=0`（通知）/ 1（透传）+ `restricted_package_name` | `message` 是 JSON：`target_type=2`（registration_id）、`notification` 内容体 | JSON：`regId` + `notifyType` + `title`/`content` | 结构与 HMS 类似：`message.notification` + `message.android` |
| 频率 / 额度 | 按应用与消息分类限额（控制台为准） | **测试权限每天仅 1000 条**；正式权限要求已上架/已申请 | 鉴权接口 10 次/s；推送按分类限额 | 按分类限额 |
| 海外 | 小米海外推送已逐步下线，海外走 FCM | `api-intl.push.oppomobile.com` | — | — |
| 官方文档 | dev.mi.com（Server API Address） | open.oppomobile.com（鉴权 / 单点推送） | dev.vivo.com.cn（推送鉴权 / 发送） | developer.honor.com |

**核实程度说明（重要）**：小米、OPPO、vivo 三家的鉴权与发送路径是从官方文档页
读到的；**荣耀那一条（`push-api.cloud.honor.com/v1/{appId}/messages:send` +
OAuth2）本轮没能打开官方文档页**（链接 404），是按公开资料写的，
真要接的时候**必须以官方文档为准**。

> 顺带一条对个人开发者最有用的：**华为 HMS Push 接受个人开发者账号**（不要求上架）。
> 如果哪天只想在华为/荣耀设备上试推送，那是最省事的一条路 —— 但覆盖面只有那两家。

## 3. 为什么这一版**没有**接厂商推送

1. **资质拿不到**：四家都要企业开发者认证（营业执照）。这个 App 是你自己用的
   英语听力工具，不是公司产品。
2. **收益为零**：这个提醒的内容是「今天还没听英语」——**本地就能算出来**，
   不需要服务器参与。厂商推送唯一多给的能力是「用户从没打开过 App 也能收到」，
   而这对一个自己每天在用的 App 没有意义。
3. **成本不低**：4 个 SDK（4~6 MB）+ 4 套服务端鉴权（token 24h 轮换、要缓存）
   + 设备 token 表 + 各厂商的「消息分类」审核（OPPO 对营销类有处罚机制）。
4. **可靠性并不更高**：见 §4。

## 4. 本地闹钟在这台机器上的真实可靠性（已写进 App 的提示文案）

| 情况 | 会怎样 | 推送能救吗 |
| --- | --- | --- |
| 进程被系统回收 / 内存不足被杀 | ✅ 照常触发（系统按时刻拉起 receiver） | 能 |
| 手机重启 | ✅ 已处理（`BOOT_COMPLETED` 重排） | 能 |
| **装新版本** | ✅ 已处理（`MY_PACKAGE_REPLACED` 重排）—— ⚠️ 少了这条，每次更新提醒就悄悄消失 | 能 |
| 飞行模式 / 断网 | ✅ 照常 | ❌ 不能 |
| 用户在设置里**强行停止** | ❌ 所有闹钟被系统清掉，直到手动再打开 App | ❌ **同样不能** |
| 国产 ROM 的后台限制 | ⚠️ 可能被冻住；需要用户放行「自启动 / 后台运行」 | 部分能（系统级通道） |

★ 所以这一版**刻意不声明** `SCHEDULE_EXACT_ALARM`：那会让「闹钟和提醒」出现在
系统权限页里、要用户额外授权一次，而这个提醒差几分钟完全无所谓 ——
没有它就退化成 `setAndAllowWhileIdle`（系统在附近叫醒），**少一次授权 = 少一个放弃的理由**。

## 5. 如果将来真的要接厂商推送：清单

按这个顺序做，每一步都有明确产出：

1. **资质**：四家开放平台注册企业开发者（要营业执照）+ 应用包名、签名登记；
   小米 / OPPO / vivo 提交上架（或用「不上架申请」）。
2. **客户端**：每家的 SDK 初始化（AppID/AppKey）+ 拿到各自的设备 token（regId）；
   在 `POST /api/push/register` 上报 `{vendor, token, deviceId}`。
   ⚠️ 一台设备可能同时有多个通道（比如小米手机也装了 HMS），上报成一张**通道表**，
   服务端按「优先用本厂商通道、其次可用的」挑一个发。
3. **服务端**：四个 sender（鉴权 + 发送 + token 失效回执处理），
   加上 token 的 24h 缓存。**每种厂商通道只发一次**，收到「token 无效」就清掉那一行。
4. **判据**：不要用「发送成功」当到达判据 —— 用**厂商回执 / 到达统计**。
   （这也是「静默吞掉」的典型：HTTP 200 只代表收了，不代表用户看到了。）

## 6. 本版实际交付

- `notify/DailyReminder.kt`：每晚 23:30（`AlarmManager`，精确优先、退化到不精确）
  + 通知频道 + **今天已达标就不打扰**；
- `notify/ReminderReceiver.kt`：到点发通知 **并重排下一次**（一次性闹钟必须重排）；
- `notify/BootReceiver.kt`：开机 / **装新版本**之后重排；
- 设置页「每日提醒」开关（默认开），并在开关下面**直说**两种情况会失效
  （系统通知权限、强行停止 / 后台限制）；
- 单测 `DailyReminderTest`：跨天边界（23:29:59 / 23:30:00 / 跨月 / 跨年）7 项。
