# 工程约定：构建 / 原生层 / 验证

> 这三块都是「碰到才查」的参考料，所以放在文档里，不占项目记忆的篇幅。
> 项目记忆（`.workbuddy/memory/MEMORY.md`）里只留最关键的判据与本文档的指针。

---

## 一、构建

- 一律走 **`./build-apk.sh`**（JDK 17 + `GRADLE_USER_HOME=~/.workbuddy/binaries/gradle-home`）。
  它做三件事：**反解产出的 versionName 命名**（文件名与真实版本号不会再各说各话）、
  **7 项断言**、跑 `tools/check-device-compat.py`。
- 那 7 项断言是：ELF 16KB 对齐、zip 条目对齐、符号版本、**dex 类**与**中文日志锚点**、
  资产字节、Manifest。
  ⚠️ **新增了类要加进 `targets` 列表**；新增了关键日志要加进 `anchors` 列表。
- 内嵌的 `python -c` 是 shell 双引号串 → **注释里禁写 `$` 与反引号**（有断言专扫这一条）。
- **锚点取完整字面量或固定前缀**：带插值的串在 dex 里会被切碎
  （`下载转写模型（` 后面的数字是算出来的，整句根本不在常量池里）。
- **不能用 `strings` 搜中文** —— 它默认只认可打印 ASCII，中文一律看不见，
  会得出一份「全部缺失」的假结论。中文在 dex 里就是 UTF-8 字节，直接字节搜。
- dex 断言「有 MISS 即 exit 1」——所以**构建成功就等于锚点全在包里**。
  但注意别被锚点名字骗了：`'仍有缺失'` 本身就是一条锚点，
  输出里的 `OK   仍有缺失` 是「这条锚点检查通过」，不是「还有缺失」。
- `appVersionCode` / `appVersionName` 必须放在 `plugins {}` **之后**
  （Gradle Kotlin DSL 要求 `plugins` 块是脚本第一个语句）。
- **依赖不随手升**：AGP 8.13.2 + compileSdk 36 + Gradle 8.14.3 + JDK 17。

## 二、原生层（sherpa-onnx / onnxruntime）

### 符号版本（最隐蔽的一个）

sherpa 要 `OrtGetApiBase@VERS_1.28.2`，而官方 `.so` 只定义了 1.28.0 →
`UnsatisfiedLinkError: cannot locate symbol "OrtGetApiBase"`
（**库和符号都在，文案却骗人**），编译期完全静默、只有真机才炸。

改 onnxruntime 版本后**必须**重跑 `FORCE=1 ./tools/vendor-sherpa-aar.sh`。

### 三层门槛（症状都是真机启动闪退、无堆栈）

1. ABI 匹配
2. ELF `p_align >= 0x4000` 且 `(p_vaddr - p_offset) % 0x4000 == 0`
3. **zip 条目 16KB 对齐且 STORED**

判据工具是 `tools/check-device-compat.py`。
⚠️ 别用 central directory 里的 extra 去算条目起点。

### 异常与线程

- `UnsatisfiedLinkError` / `OutOfMemoryError` 继承的是 **`Error` 不是 `Exception`** →
  碰 JNI 的兜底一律写 `catch (Throwable)`。
- **线程上限 4** 是按大小核机型设的；要调先拿 `diag/DeviceInfo` 的真机数据。
- **协程未捕获异常 = 进程级崩溃**：Player API 只能在主线程调
  （计时器读 `isPlaying` 挂错调度器 → 一播放就闪退）。
  主线程 scope 读播放器，另开 scope 算重活。
- `AsrEngine.release()` 需要 **activeSessions 活跃计数**（accept 全程持标记），
  否则会在 decode 进行中 free 掉 630 MB → SIGSEGV。重试写循环，不写递归。

## 三、验证方法论（写断言时的纪律）

### 断言必须有**分辨力**

一条永远为真的断言比没有断言更糟 —— 它让人以为「这里已经被守住了」。
每一条关键判据都要配一个**坏样本**，要求断言在坏样本上**失败**。

已经踩过的**四种**「假通过 / 假失败」：

| 坑 | 实例 |
|---|---|
| 模式恒真 | `"morphVisible," in src` —— 后半段永远成立，等于没检查 |
| 模式匹配到注释 | `PIPE.count("这条音频读不出来")` 数到了注释里的引用 → 假失败。要改用带上下文的 `Failed("这条音频读不出来` |
| 替换打在注释上 | 坏样本用 `replace("YOUR_SERVER_IP", …)`，而第一次出现是在**注释正文**里 → 标签没变，坏样本「看起来生效了其实没有」 |
| ★★ **「该变没变」被提前 `continue` 挡住** | 3.1.0 的 `/vocab/` 收口检查：`if not changed: continue` 写在「期望 200→404」**之前** —— 于是**收口根本没做**时 `changed` 为空、直接跳过、报通过。而「收口没做」正是这条检查存在的**唯一理由**：它在最坏情况下（什么都没干）恰好恒真。**坏样本 2 当场抓住的。** 写「预期变更」类断言时先问一句：**这个判据在最坏情况下还成立吗？** |

### 其它反复踩到的

- **`count("xxx")` 要带左括号**：不带的话 `import detectVerticalDragGestures` 那一行
  也会被数进来（2≠1，假失败）。
- **别用定长窗口去截源码找上下文**：给某个调用点补了几行注释，窗口就够不着了
  （`verify-ui-flows` 从 400 加到 900 就是这么来的）。
  改成按锚点定位，而不是按字符偏移。
- **`strip_comments` 会把字符串字面量换成 `""`** → 任何**含字面量**的模式
  都不能拿剥过的源码去匹配（永远匹配不上，是假失败）。要用原始源码。
- **注意前缀差异**：`GATE` 在引擎里是 `!modelReady() && !ServerConfig.ENABLED`，
  在 Worker 里是 `!app.container.provisioner.isReady() && !ServerConfig.ENABLED` ——
  同一个语义、不同的前缀，整串匹配会失配。
- **断言「出现了几次」是拦不住「漏改一处」的唯一办法**：
  同一语义的门禁散在四处（引擎 / Worker / 插队 / 回前台），
  只改三处时，只有 `count(GATE) == 2` 这类断言能发现。
- **每跑一次 `run-all-verify.sh` 都要看数字变化**：
  脚本自报项数会因为清单内容变动而变化（`verify-firstrun-deploy.py` 在 262/265/266 之间
  跳过）——清单里写的数字要以**最后一次实测**为准。

### 三条「会误报」的断言写法（都实际踩过，已从 MEMORY.md 搬来）

- ★★ **反向断言（「必须已缺席」）必须用带包路径的全名。**
  裸类名会撞上依赖库里的同名类 —— 实测 `Tokenizer`、`AudioDecoder` 在 dex 里各命中一次，
  都不是我们的。后果是断言**恒为假失败**，而假失败会让人不再跑构建断言。
  **同一类坑已踩三次**（`diag/DeviceInfo`、`checkin/Tick`、上述两个）。
- ★★ **别断言「没有 .so」这种想当然的结论。**
  包里还有 8 个（Compose 的 `graphics.path`、DataStore 的 `shared_counter` × 4 ABI，各约 10 KB）。
  判据要收窄到**具体库名**。**一条会误报的断言比没有断言更糟** ——
  它逼下一个人去放宽它，而放宽的那一刻真判据也没了。
- ★ **`unzip -l <apk> <pattern>` 无匹配时返回 11**，而构建脚本是 `set -e` →
  「产物正是我们要的（没有资产）」会让构建**静默退出**。必须 `|| true`。
  且它的末行是汇总行（`20456  2 files`），别拿 `awk '{print $2}'` 当文件数。
- ★ **断言别写死「数量」或旧符号**：`count(...) == 1`、绑死某个实现串，
  下次合法改动就假失败 —— 而**假失败会让人不再跑这个脚本**（比没有断言更糟）。
  判「性质」而不是判数量；断言要跟着实现改，并在注释里写清**为什么这次要改**。
