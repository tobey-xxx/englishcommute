## 内容与数据策略
- **下载策略在纯函数 `content/ContentPolicy.kt`，2.1.9 起是懒加载的**
  （`selectPrefetch`：接下来 N 条未听完的 ∪ 收藏 ∪ 在播 ∪ **每源保底**）。
  **每源保底不是体验问题而是正确性问题** —— 周更源不预取 → 没音频 → 被 purge 清掉
  → **整个源消失**。还有 `purgeStaleIndex`（否则留死条目）。
  ⚠️ **保留期的配对（3.2.0 前的旧版已作废，别照旧文档改）**：下载不再看发布时间，
  所以旧的「下载窗口 2 天 < 保留期 3 天」不成立了；现在的配对是
  「**本地保留期 3 天 < 服务端音频保留期 7 天**」。保留期基准是 `Episode.downloadedAt`
  —— **不是文件 mtime（播放会刷）、不是 publishedAt**。
  ⚠️ 没预取到的条目**仍然可点** → `SyncEngine.requestDownload`。
- 三个静默陷阱（锁在 `tools/verify-retention.py`）：refreshFeeds 漏传 `downloadedAt` / 老索引迁移
  补 `publishedAt` / 什么都不补 → 都是「永不删」。**正解补 `now`**。
- 删除前四道豁免：收藏 / **正在播的那条** / `status.isBusy` / 无音频（`NowPlaying` 是唯一
  「当前播放」登记点）。ExoPlayer 队列是快照 → 被删 id 要 `prunePlaylist`，
  **`removeMediaItem` 必须主线程**。
- **播放队列 = 纯函数 `player/PlaybackQueue.order()`**（未听完 + 已听完，各按时间倒序）；判据用
  `PlaybackPositions.done` 二值标记，**不能用断点位置**；已听完只往后排不移出。
- **打卡**：日键 `Math.floorDiv(millis + offset, DAY_MS)`（不用 `LocalDate`）；计时器挂
  `PlaybackService` 的 Player（挂 ViewModel 则锁屏不计）；`justCompleted` 由数据层算，
  是海报与庆祝的**唯一**触发源（不落盘，否则次日重放）。
  ⚠️ **3.3.0：每日目标从常量变成了持久化的设置项**（`goalMinutes`）——
  但上面那句不变式**一个字没变**：只有秒数是原始数据，`done` 一律按**当前**目标现算。
  代价是**改目标会重算全部历史**（连续天数可能掉），所以 `setGoalMinutes` 必须把变化
  当场报给用户。⚠️ `reset()` 只按 `sec:` / `poster:` 前缀删 —— `goal` **刻意不带前缀**，
  配置不该被「清空记录」带走。
- **倍速是整百分数 Int（50..200 步长 5）**（`settings/SpeedPolicy.kt`）；格式化必须补零
  （否则 `1.05x` 显示成 `1.5x`）；精听取 `min(用户倍速, 0.7)`。
- **卸载语义**（`verify-ship-contract.py` 的 A2 节守）：`hasFragileUserData=false`
  （否则卸载框里会多出「保留数据」）、`allowBackup=true` + 两个备份规则 XML。
  ⚠️ 2.1.0 删掉端侧模型之后，原先那套「就绪判据 / `.owner` = installId / 无记录就保留」
  （`asr/AsrModelFiles.kt`、`ModelProvisioner`）**已随功能一起不存在** ——
  别再照旧笔记去找那两个类。
- **备份规则的 `domain`/`path` 写错静默不生效**（`external`=getExternalFilesDir，`file`=filesDir）；
  超限是**整次备份失败**；XML 开始标签属性之间不能写注释。

## 界面与动效

**完整约定在 `EnglishCommute/界面约定.md`**；通用做法在 skill `android-compose-gesture-dismiss` /
`-list-ux` / `-dual-theme`。最容易出事的三条：

- **界面里不许散落 `tween(...)`**（统一走 `Motion.kt`，构建断言会扫）。★ 两条曲线曾
  「实现与注释相反」，**只有算起手斜率才发现**（2.25 / 4.25）。
- ⚠️ **Compose 没有 `backdrop-filter` 等价物**（`Modifier.blur` 模糊的是自己）——别再以为能做真
  背景模糊。**无障碍开关必须走 Compose 状态**（`@Volatile var` 能编译能改值，但**没有读者**；
  方法名是 `isHighContrastTextEnabled`）。
- ⚠️⚠️ **覆盖层内 `remember` 的状态会跨「关闭 → 再打开」存活**（退出动画 220ms 内再次打开会取消
  退出、保留实例）→ `LaunchedEffect` 不重跑 → 页面停在屏幕外。判据：日志里只有「迷你条点开」
  而没有紧跟的「进入播放页 · 」。正解：自增 `openNonce`。
- **同一件事只能有一个入口/一个答案**：打卡海报曾三处各写一份 `render`，而**庆祝页那份只
  「等文件 4 秒」** → 用户报「庆祝页生成不出海报」。**单独看任何一处都发现不了。**

## 并发与落盘 / 让位纪律
- **RSS 并发 4**（`Semaphore`）+ **合并留单线程**；**下载与转写用 `Channel` 解耦**，转写侧保持
  单协程（并发推理叠 O(L²) 激活）。**索引落盘：高频防抖 / 删除类立刻 / 一律 tmp+rename** ——
  裸 `writeText` 被杀留半截 JSON，而 `load()` 静默吞异常 → 「素材库突然空了」。
- **服务级的忙碌判断不能与引擎级脱节**（1.2.1，最贵的一条）：`work.isActive` 拒绝 `MODE_SYNC`
  时让窗口长达十几分钟 → 「更新」被静默吃掉，**看起来像按钮接反了**。三条铁律：
  ① 用户的明确动作**不许静默丢弃**（登记 → 让位 → 补做）；② 让位点要细（翻译到句级、转写到轮级）；
  ③ 让位不丢进度（用返回值 `Yielded` 而不是取消协程 —— 阻塞调用不响应 cancel，且
  `catch (Exception)` 会吞掉 `CancellationException`）。**提前 return 的路径不许改通知**。

## 通知 / 日志
- **通知 ID 只在 `EnglishCommuteApp` 定义一处、两两不同**（标识是「包名+tag+id」，**id 相同就是
  同一条**）。⚠️ **media3 默认 ID 就是 1001**（javap 实测）：1001 播放（**显式** setNotificationId）
  / 2001 进度 / 2002 收尾。
- **措辞必须与「这一轮在干什么」一致**：补转写那轮 `fetched` 恒为 0，说「更新完成 · 共 N 条可用」
  就是谎话（判据 `SyncPhase.Done.produced`）。**终态不进 ongoing 通知**；什么都没干的一轮不发
  收尾通知（用户主动点的那轮例外）。撤进度通知三条路径：`finally` + `onDestroy` + 冷启兜底。
- `DiagLog.act()` 覆盖**用户动作 + 状态迁移 + 通知收发 + 前后台切换**，**不记每帧都变的值**；
  ⚠️ 状态迁移挂**播放服务**（锁屏/蓝牙/连播不经过界面）。写盘**统一过滤控制字符**（含 NUL →
  ripgrep 判二进制并停止整文件匹配）；单文件 1 MB / 留 4 份；⚠️ `verify-copy-audit.py` 对着
  **所有字面量**扫，日志措辞也得用人话。
